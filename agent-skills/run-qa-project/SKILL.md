# run-qa-project — маршрут заказа

Тонкий роутер. Источник правды — `D:\Rabota\llm-qa-wiki`, машиночитаемый маршрут —
`resources\qa-pipeline-contract.json`.

Скилл не выполняет работу сам: он определяет, какая фаза следующая, и передаёт управление профильному
скиллу.

## Когда использовать

- Новый заказ на тестирование, нужен полный маршрут.
- Работа прервалась, надо понять, на чём остановились.

## Когда не использовать

- Нужна одна конкретная фаза — вызывай её скилл напрямую.
- Разовая проверка одной формы: открой чек-лист, отчёт формата Test Management здесь избыточен.

## Маршрут

| Фаза | Скилл | Артефакт |
|---|---|---|
| Приём объекта | `qa-intake` | `_qa-intake.md` |
| Тест-план | `qa-plan` | `_qa-plan.md` |
| Тест-дизайн | `qa-design` | `_qa-cases.md` |
| Прогон | `qa-execute` | `_qa-run.md` + `evidence\` |
| Дефекты | `qa-defects` | `_qa-defects.md` |
| Отчёт | `qa-report` | `_qa-report.json` + XLSX |
| Фиксация опыта | `qa-capture` | `_qa-learning-review.md` |

## Шаги

1. **Определи каталог проекта:** `D:\Rabota\projects\<проект>`. Создай, если его нет.
2. **Узнай состояние маршрута:**

   ```
   pwsh D:\Rabota\llm-qa-wiki\tools\verify-qa-pipeline.ps1 -ProjectRoot D:\Rabota\projects\<проект>
   ```

   Команда покажет статус каждой фазы и назовёт следующую. Фаза считается закрытой, когда её артефакт
   существует и непуст — состояние живёт в файлах, а не в памяти агента, поэтому маршрут переживает
   перезапуск сессии.
3. **Прочитай артефакты закрытых фаз** прежде, чем продолжать. Без них следующая фаза пойдёт по
   догадкам.
4. **Вызови скилл следующей фазы.** Одна фаза за раз: её quality gate должен быть пройден до
   перехода дальше.
5. **Не пропускай фазы.** Кейсы без плана дают покрытие наугад; отчёт без валидатора уезжает
   заказчику с битой трассируемостью.
6. **Артефакт.** Поддерживай `_qa-pipeline-status.md`: текущая фаза, что закрыто, что осталось,
   открытые вопросы к заказчику.

## Quality gate

- Каждая пройденная фаза оставила непустой артефакт.
- Ни одна фаза не начата раньше своих зависимостей.
- Открытые вопросы к заказчику зафиксированы, а не додуманы.
- Финальный отчёт прошёл валидатор.

## Кросс-рантайм

Маршрут одинаков во всех агентных рантаймах. Ни один обязательный шаг не опирается на MCP-сервер или
инструмент конкретного рантайма: исполняемая часть — Python 3 и PowerShell 7. MCP-браузер допустим как
ускоритель разведки в фазе `qa-execute`, но результат от него зависеть не должен.

Перечень поддерживаемых рантаймов и порядок раскатки скиллов — в `D:\Rabota\AGENTS.md`.
