# Таксономия дефектов

Типовые дефекты по областям с обоснованием severity. Служит двум целям: ускоряет и объективирует
оценку severity при оформлении и снабжает
[предугадывание ошибок](../docs/03-test-design/error-guessing.md) конкретным списком проверок.

## Как пользоваться

При оформлении дефекта найти близкий тип и взять его severity как отправную точку. Отклонение от неё
допустимо, но требует объяснения в описании: контекст проекта меняет влияние.

При планировании проверок пройти таксономию по областям, релевантным объекту, — это дешёвый способ
добрать проверки, которые формальные техники не дают.

## Шкала severity

| Severity | Критерий |
|---|---|
| `Critical` | функция недоступна, обходного пути нет; потеря или утечка данных |
| `Major` | функция работает неверно; есть неудобный обходной путь |
| `Minor` | отклонение заметно, но цель достижима |
| `Trivial` | косметика |

Подробнее — [severity против priority](../docs/05-defect-management/severity-vs-priority.md).

## Пополнение

Новый тип добавляется, когда дефект встретился второй раз или когда он был пропущен в прод. Запись
содержит: проявление, типовую причину, severity с обоснованием, способ проверки. Без способа проверки
запись бесполезна — она не превращается в кейс.
