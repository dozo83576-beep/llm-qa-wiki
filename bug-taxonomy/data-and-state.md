# Дефекты данных и состояния

Самая дорогая группа: здесь теряются данные, деньги и приватность.

## Доступ к чужому объекту по прямому идентификатору

**Проявление.** Подстановка чужого идентификатора в адрес открывает чужой заказ, профиль или
документ.

**Причина.** Проверяется факт аутентификации, но не право на конкретный объект.

**Severity: `Critical`.** Утечка персональных данных, юридические последствия.

**Как проверить.** Войти под одним пользователем, взять запрос из панели сети, подставить
идентификатор объекта другого пользователя. Подтвердить факт и остановиться, см.
[безопасность](../docs/11-security-accessibility/security-basics.md).

## Запрещённый переход состояния выполняется

**Проявление.** Отменённый заказ можно оплатить, отправленный — отменить.

**Причина.** Кнопка скрыта в интерфейсе, но сервер действие не запрещает.

**Severity: `Critical`** при участии денег или отгрузки, иначе `Major`.

**Как проверить.** Отправить запрос действия напрямую для объекта в неподходящем состоянии. Отдельно
— сценарий двух вкладок: в одной отменить, в другой нажать «Оплатить».

## Действие старым токеном после выхода

**Проявление.** После выхода из аккаунта прежний запрос всё ещё выполняется.

**Причина.** Сессия не завершается на сервере, только очищается на клиенте.

**Severity: `Critical`.** Особенно на общем компьютере.

**Как проверить.** Сохранить запрос, выйти из аккаунта, повторить запрос.

## Потеря данных при обновлении приложения

**Проявление.** После обновления пропадают авторизация, настройки, черновики.

**Причина.** Миграция локального хранилища не реализована или падает.

**Severity: `Critical`.** Массово затрагивает всех пользователей при выкладке.

**Как проверить.** Установить предыдущую версию, накопить данные, обновить поверх, см.
[установка и обновление](../docs/07-mobile-testing/install-update-store.md).

## Корзина затирается при входе

**Проявление.** Товары, добавленные без авторизации, исчезают после входа в аккаунт.

**Причина.** Корзина аккаунта заменяет гостевую вместо объединения.

**Severity: `Major`.** Прямая потеря заказа.

**Как проверить.** Добавить товары без авторизации, войти в аккаунт с непустой корзиной.

## Устаревшее состояние страницы

**Проявление.** Страница открыта давно, объект успел измениться; действие выполняется по старым
данным.

**Причина.** Отсутствие проверки актуальности состояния при отправке.

**Severity: `Major`.** Повышается до `Critical`, если приводит к неверному списанию.

**Как проверить.** Открыть объект в двух вкладках, изменить в одной, выполнить действие в другой.

## Смесь старого кэша с новой версией

**Проявление.** После выкладки часть пользователей видит сломанную вёрстку.

**Причина.** Ресурсы кэшируются без обновления идентификатора версии.

**Severity: `Major`.** Проявляется только у части пользователей, поэтому обнаруживается поздно.

**Как проверить.** Открыть сайт до выкладки, выложить, вернуться без очистки кэша.
