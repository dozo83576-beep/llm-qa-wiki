# Скрытая мобильная копия блока ломает автоматический прогон

На адаптивных сайтах один и тот же блок часто выведен дважды: мобильная версия и десктопная. В
разметке мобильная копия обычно идёт **первой** и скрыта классом вроде `d-lg-none`. Автоматика,
берущая первый совпавший элемент, попадает в невидимую копию и падает по таймауту.

## Назначение

Перестать чинить каждый упавший кейс по отдельности, когда причина у них общая и лежит в вёрстке, а
не в сценарии.

## Когда использовать

- Прогон падает с `element is not visible`, `element is not enabled` или таймаутом клика, хотя тот
  же элемент вручную виден и кликается.
- Сайт адаптивный, в разметке встречаются `d-none`, `d-lg-none`, `d-lg-inline-flex` и подобные.
- Падает сразу несколько кейсов в разных областях — признак общей причины.

## Когда не использовать

- Элемента действительно нет на странице: тогда это находка о системе, а не проблема селектора.
  Отличать по трассировке — см. «Как поймать».
- Одностраничное приложение без адаптивного дублирования.

## Как это делается

Добавить к селекторам фильтр видимости и применить его сквозным патчем конфига, а не по одному
кейсу:

```python
ACTIONS = {'click', 'fill', 'check', 'uncheck', 'press', 'waitForSelector'}
for case in config['cases']:
    for step in case.get('steps', []):
        sel = step.get('selector')
        if not isinstance(sel, str) or step.get('action') not in ACTIONS:
            continue
        if '>> nth=' in sel or ':visible' in sel:
            continue
        parts = [x.strip() for x in sel.split(',')]
        step['selector'] = ', '.join(x + ':visible' for x in parts)
```

`:visible` понимает CSS-движок Playwright, в том числе вместе с `:has-text()`. Для блоков, у которых
видимая версия отличается классом, надёжнее указать её прямо: не `text=Найдено`, а
`.default-block.d-lg-inline-flex`.

Отдельный случай — элемент с нулевым размером внутри свёрнутого предка (аккордеон, вкладка). Здесь
`:visible` не спасёт: сначала нужен шаг, раскрывающий предка.

## Почему это работает

Playwright ждёт от элемента состояния «видим, доступен, стабилен». Скрытая копия никогда его не
достигает, поэтому клик уходит в таймаут на 45 секунд — и так на каждом кейсе. Фильтр видимости
сдвигает выбор на ту копию, которую реально видит пользователь, то есть на ту, поведение которой мы
и проверяем.

## Как поймать

Включить трассировку и прочитать, какой именно узел резолвился:

```
"diagnostics": { "trace": "failures" }
```

```bash
python -c "import json;[print(json.loads(l).get('message','')) for l in open('trace.trace',encoding='utf-8') if '\"type\": \"log\"' in l]"
```

Строка `locator resolved to <div class=... >` с последующим `element is not visible` при том, что
элемент виден глазами, — точный признак этого случая.
