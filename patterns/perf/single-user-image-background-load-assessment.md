# Оценка загрузки изображений и фонов для одного пользователя

Воспроизводимый способ превратить субъективное впечатление «графика загружается быстро или медленно»
в проверяемый результат без имитации многопользовательской нагрузки.

## Назначение

Отделить скорость появления полезного содержимого от события полной загрузки страницы и от
догрузки невидимых ресурсов. Вывод связывается с реальным viewport, условиями сети, медианами
повторных прогонов и ошибками запросов.

## Когда использовать

- В функциональном или адаптивном тестировании страницы требуется субъективно оценить изображения
  и фоны.
- Нужно сравнить desktop и мобильные viewport в одинаковых условиях.
- Нет разрешения или потребности создавать нагрузку на сервер.

## Когда не использовать

- Для проверки поведения под числом одновременных пользователей: нужен согласованный нагрузочный
  сценарий на отдельном стенде.
- Для утверждения SLA или универсального порога без требования продукта и согласованного профиля
  сети и устройства.
- Для вывода по одному прогону или по прогретому пользовательскому профилю.

## Как это делается

1. Зафиксировать URL или тип маршрута, locale, browser и ОС, viewport, тип устройства или
   эмуляции, состояние кэша, профиль CPU и наличие либо отсутствие network throttling.
2. Для каждой среды выполнить не менее трёх прогонов. Каждый прогон начинать в новом изолированном
   browser context без унаследованных cookies, HTTP cache и service worker state.
3. До прокрутки снять четыре независимые группы данных:
   - FCP — когда пользователь впервые увидел содержимое;
   - LCP — когда появился основной крупный элемент;
   - `load` — когда браузер завершил обычную загрузку документа и зависимых ресурсов;
   - готовность изображений и CSS-фонов первого viewport, включая число запущенных неуспешных
     запросов.
4. Для видимых `<img>` проверить `complete`, ненулевые `naturalWidth` и `naturalHeight`, а при
   необходимости завершение `decode()`. Для видимых CSS-фонов сопоставить вычисленный
   `background-image` с успешной записью Resource Timing либо сетевым ответом.
5. После фиксации первого экрана выполнить отдельный этап прокрутки. Дождаться появления каждого
   проверяемого lazy-блока и повторить проверку его изображений и фонов. Не смешивать время этой
   стадии с метрикой первого viewport.
6. Рассчитать медиану FCP, LCP, `load` и готовности графики первого экрана по каждой среде; дополнить
   минимумом и максимумом, если разброс влияет на вывод.
7. Сформулировать субъективный результат вместе с условиями, медианами и числом неуспешных запросов.
   При отсутствии продуктового порога использовать формулировку наблюдения, а не Pass/Fail по
   выдуманному нормативу.

## Что считать ошибкой изображения

- Видимое `<img>` с завершённой попыткой загрузки и нулевым `naturalWidth` — битое.
- Запущенный запрос изображения или фона с сетевой ошибкой либо недопустимым HTTP-ответом —
  неуспешный запрос.
- Невидимое вне viewport изображение с `loading="lazy"`, запрос которого ещё не запускался, не
  является битым. Оно проверяется только после отдельной контролируемой прокрутки.
- Элемент, скрытый адаптивной раскладкой и не предназначенный для текущего viewport, не включается
  в число ресурсов первого экрана.

## Почему это работает

FCP, LCP и `load` отвечают на разные вопросы и не доказывают готовность конкретной графики сами по
себе. Изолированный холодный context исключает случайное преимущество кэша, медиана уменьшает
влияние единичного сетевого выброса, а разделение первого экрана и lazy-стадии не превращает
корректно отложенные ресурсы в ложные дефекты.

## Как поймать

Результат не принимается, если отсутствует хотя бы один пункт:

- не менее трёх изолированных прогонов на среду;
- locale, viewport, cache state и network throttling записаны явно;
- по каждой среде есть медианы FCP, LCP, `load` и готовности графики первого viewport;
- указано число неуспешных запросов изображений и фонов;
- lazy-контент проверен отдельной прокруткой либо явно исключён из области проверки;
- невызванные offscreen lazy-ресурсы не попали в список битых;
- субъективный вывод содержит условия и числа, на которых он основан.
