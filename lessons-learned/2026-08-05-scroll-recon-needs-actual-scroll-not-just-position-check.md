# «position: static» у шапки не значит, что шапка не фиксируется при прокрутке

## Что случилось

На заказе по анализу шапки интернет-магазина разведка на старте (`_qa-intake.md`) сняла
`getComputedStyle` шапки на нескольких значениях `scrollY` и не нашла ни одного элемента с
`position: fixed`/`sticky` в верхней зоне экрана. Вывод «шапка не фиксируется при прокрутке» ушёл в
интейк как установленный факт. Позже, уже на фазе прогона, при более внимательной проверке (клик по
дропдауну, который вёл себя странно после прокрутки) в DOM обнаружился отдельный виджет —
компактная копия шапки с `position: fixed`, которая появляется только при пересечении порога
прокрутки между 150 и 200 px. До этого порога элемент существовал в DOM с нулевыми размерами и не
совпадал ни с одним фильтром «видимый fixed-элемент». Первоначальный вывод пришлось задним числом
исправлять в уже написанном `_qa-intake.md`.

## Почему это дороже, чем кажется

Ошибочный факт в интейке распространяется на тест-план и тест-дизайн: кейсы на «поведение при
прокрутке» проектировались бы под неверную модель поведения системы. Опоздавшее обнаружение
означало переписывание уже готового документа задним числом вместо правки на этапе, где это дёшево.
Разница между «шапка не фиксируется» и «шапка переключается в липкую копию за порогом» — не
формальность: вторая версия открывает совершенно другой класс проверок (что происходит с открытыми
элементами исходной шапки в момент переключения) и другой класс дефектов (какой оказался этим
заказом: раскрытый список остаётся висеть под появившейся копией).

## Что делать

Когда проверяешь поведение шапки/навигации при прокрутке → не ограничивайся снятием
`getComputedStyle`/`getBoundingClientRect` **в состоянии покоя и на нескольких фиксированных
`scrollY`**. Обязательно: (1) реально проскроллить через диапазон значений с мелким шагом (не только
крупные скачки 200/400/800), (2) на каждом шаге искать элементы, которых не было на предыдущем шаге
(а не только те, что уже найдены в начальном снимке), (3) если что-то похожее на дубликат шапки
нашлось — проверить его функционально (клик по логотипу/пункту меню внутри него), а не только
геометрически.

## Как поймать

В скрипте разведки прокрутки: на каждом шаге `scrollTo` сравнивать список `position: fixed |
sticky`-элементов с предыдущим шагом и логировать разницу (`appeared`, `disappeared`), а не только
финальный список на последнем `scrollY`. Пустой список `fixed`-элементов на **одном** шаге — не
основание для вывода «шапка не фиксируется»: нужен пустой список на **всех** шагах диапазона,
включая мелкий шаг вокруг вероятных порогов (100–250 px).
