# Доказательства адаптивности локализованной главной страницы

Обезличенный разбор проверки главной страницы в desktop, мобильном портрете и мобильном альбоме на
локализованном маршруте вида `/<locale>`.

# Задача

Проверить ключевые блоки, масштабирование, отступы, меню, кнопки, формы, всплывающие окна,
горизонтальный скролл, читаемость и загрузку графики. Для каждого результата требовалось оставить
доказательство, которое однозначно соответствует шагам и ожидаемому результату тест-кейса.

# Что сработало

- Состояния интерфейса снимались по правилу «кадр должен доказать кейс» —
  [паттерн смысловых скриншотов](../../patterns/ui/fullscreen-web-screenshot-evidence.md).
- Переходы получили именованные кадры «до/после», а невидимые свойства — измерения overflow,
  состояния элемента и времени навигации в PNG и manifest.
- Все кадры были просмотрены на contact sheet, а точные дубликаты основных PNG стали блокирующей
  ошибкой прогона.
- Субъективная оценка загрузки изображений и фонов была отделена от нагрузочного тестирования и
  подкреплена повторными холодными замерами —
  [паттерн оценки загрузки графики](../../patterns/perf/single-user-image-background-load-assessment.md).

# Как проверили

- Повторно выполнены 23 тест-кейса в трёх viewport; создано 34 PNG с кадрами результата и переходов.
- SHA-256-проверка всех PNG не обнаружила ни одной группы точных дубликатов.
- Для интерактивных переходов сопоставлены шаги, фактический результат, основной кадр и именованные
  состояния «до/после».
- Новый кадр одного негативного сценария уточнил наблюдение: после нажатия кнопки исходная панель
  осталась открыта, а ожидаемое модальное окно не появилось. Статус Fail сохранился, но описание
  фактического результата было исправлено по доказательству.
- Итоговый отчёт прошёл проверку структуры и трассируемости между кейсами, прогоном, дефектами и
  файлами доказательств.

# Как повторить

1. Зафиксировать локаль, полный маршрут и три среды: desktop, мобильный портрет и мобильный альбом.
2. Для каждого кейса определить наблюдаемое конечное состояние; для перехода заранее назначить
   кадры «до/после», а для невидимого свойства — измеряемую метрику.
3. Выполнить кейсы, построить manifest и contact sheet, проверить смысловое соответствие каждого
   основного кадра.
4. Заблокировать набор при точных дублях основных PNG или при кадре, который не показывает
   заявленный результат.
5. Пересобрать отчёт из источника данных после любого уточнения фактического результата.

# Когда НЕ повторять

- Не заменять парой скриншотов видео, если важен непрерывный жест, анимация или кратковременный сбой.
- Не считать замер одного пользователя нагрузочным тестированием и не создавать искусственную
  нагрузку на production без отдельного разрешения.
- Не переносить в вики адрес объекта, название заказчика, реальные данные или материалы заказа.
