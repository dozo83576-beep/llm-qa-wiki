# AGENTS.md — правила работы с QA-вики

Канон для всех агентных рантаймов. Claude Code читает его через `D:\Rabota\CLAUDE.md`, Codex — напрямую.

## Что это

Практическая база знаний по QA-тестированию плюс система скиллов. Источник правды по всему, что
касается видов тестирования, техник тест-дизайна, оформления документации и формата отчёта.

## Прежде чем писать своё

Поиск по вики дешевле, чем изобретение заново:

```
pwsh D:\Rabota\llm-qa-wiki\tools\ask-wiki.ps1 "<тема>"
```

## Сохранение знаний

После задачи — фаза `qa-capture`. Запись должна отвечать на вопросы: какая задача решалась, что
сработало или не сработало, чем это подтверждено, как повторить или предотвратить, какие документы
обновить.

| Что произошло | Куда |
|---|---|
| Повторяемый приём | `patterns/<область>/<имя>.md` |
| Типовой дефект встретился повторно | `bug-taxonomy/<область>.md` |
| Короткий вывод из провала | `lessons-learned/YYYY-MM-DD-<тема>.md` |
| Разбор проекта | `case-studies/successes/` или `case-studies/failures/` |
| Новый критерий проверки | `checklists/<имя>.md` |

Перед созданием файла проверь существующие — обновляй, а не плоди дубли. Если переиспользуемого
знания нет, явно зафиксируй в ответе `wiki artifact не нужен` и причину.

## Кросс-рантайм

Всё вносимое обязано работать и в Claude Code, и в Codex:

- **ни один обязательный шаг пайплайна не опирается на MCP-сервер или инструмент конкретного
  рантайма.** MCP-браузер и подобное — необязательные ускорители;
- исполняемая часть — Python 3 и PowerShell 7, доступные обоим;
- генератор отчёта использует только `openpyxl`, без библиотек, привязанных к агенту;
- скилл состоит из `SKILL.md` (общий) и `agents/openai.yaml` (нужен Codex, безвреден Claude Code).

Канон скиллов — `agent-skills/`. Рантайм-копии в `~/.claude/skills` и `~/.codex/skills` правке не
подлежат: их перезапишет следующая раскатка.

```
pwsh D:\Rabota\llm-qa-wiki\agent-skills\sync-skills.ps1 -DryRun
pwsh D:\Rabota\llm-qa-wiki\agent-skills\sync-skills.ps1
pwsh D:\Rabota\llm-qa-wiki\tools\verify-agent-skills.ps1 -VerifyUserRuntimes
```

## Стандарт документа

Шесть обязательных полей frontmatter, структура секций. Маркеры `TODO`, `TBD`, `FIXME` запрещены —
незавершённое либо дописывается, либо не коммитится. Подробно — `docs/00-start-here/document-standard.md`.

## Отчёт

Формат поставки зафиксирован в `docs/14-templates/xlsx-test-management.md` и проверяется валидатором
посимвольно. Отклонения от него согласуются с заказчиком до начала работ, а не в момент сдачи.

Отчёт не отправляется без прогона валидатора.

## Безопасность

- Security- и нагрузочные проверки — только с письменным разрешением владельца системы, с
  зафиксированными границами и окном времени.
- Найденную уязвимость подтверждают минимальным действием и останавливаются. Эксплуатация и выгрузка
  чужих данных недопустимы.
- Персональные данные, реквизиты заказчиков, учётные данные и содержимое договоров не попадают в
  вики, в Git, в логи, в скриншоты и во внешние сервисы.
- Кейсы в вики обезличиваются: описывается тип объекта, а не клиент.
