# Playbooks

Сквозные маршруты под типовые заказы. Playbook отвечает на вопрос «что делать по порядку», собирая
чек-листы, техники и разделы вики в один проход.

- [QA лендинга](landing-page-qa.md) — сайт-визитка, одностраничник, промо.
- [QA интернет-магазина](ecommerce-qa.md) — каталог, корзина, оформление, оплата.
- [QA мобильного приложения](mobile-app-qa.md) — iOS и Android.
- [QA API](api-qa.md) — сервис без интерфейса или проверка бэкенда отдельно.
- [Регресс перед релизом](regression-before-release.md) — повторный прогон после изменений.

## Как выбрать

| Объект | Playbook | Ориентировочный объём |
|---|---|---|
| Лендинг, визитка | [лендинг](landing-page-qa.md) | 4–8 часов |
| Корпоративный сайт с формами | [лендинг](landing-page-qa.md) + разделы каталога | 1–2 дня |
| Интернет-магазин | [магазин](ecommerce-qa.md) | 3–5 дней |
| Мобильное приложение | [мобильное](mobile-app-qa.md) | 3–5 дней |
| Сервис без интерфейса | [API](api-qa.md) | 1–3 дня |
| Повторный прогон | [регресс](regression-before-release.md) | 20–40% исходного объёма |

Оценки — отправная точка для разговора, а не обязательство. Уточняются после
[qa-intake](../00-start-here/skill-system.md) на реальном объекте.

## Общая часть любого маршрута

Независимо от типа объекта:

1. Зафиксировать объект, окружение, границы скоупа и доступы.
2. Выбрать виды тестирования от свойств объекта, а не по списку.
3. Оценить риски и распределить объём.
4. Пройти чек-листы исследовательской сессией.
5. Оформить кейсы на то, что идёт в отчёт.
6. Собрать доказательства для каждого провала.
7. Разобрать находки: объединить, разделить, отклонить.
8. Собрать отчёт и прогнать валидатор.
9. Зафиксировать опыт в вики.
