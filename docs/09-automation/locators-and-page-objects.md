# Локаторы и page object

Способ найти элемент и способ организовать код. Обе вещи определяют, переживёт ли набор автотестов
следующий редизайн.

## Когда использовать

- Любой браузерный автотест, который проживёт дольше одного дня.

## Когда не использовать

- Одноразовый скрипт для добычи одного факта в баг-репорт. Там достаточно прямого селектора, и
  вкладываться в структуру незачем.

## Приоритет локаторов

Сверху вниз, первый доступный выигрывает:

1. **Роль и доступное имя** — кнопка с текстом «Отправить». Устойчиво к правкам вёрстки, заодно
   косвенно проверяет [доступность](../11-security-accessibility/accessibility-wcag.md): если элемент
   не находится по роли, его не найдёт и скринридер.
2. **Тестовый идентификатор** — специальный атрибут, добавленный для тестов. Самый надёжный вариант,
   требует договорённости с разработкой.
3. **Видимый текст** — для ссылок и заголовков. Ломается при смене формулировок и локализации.
4. **Семантический CSS** — по идентификатору или устойчивому классу.
5. **Цепочка CSS или XPath по структуре** — крайний случай. Ломается от любой правки вёрстки.

## Правила

- Локатор описывает, **что** ищем, а не **где** оно лежит. `nav > ul > li:nth-child(3) > a` ломается
  от добавления пункта меню.
- Индексы вроде «третий элемент» использовать только там, где порядок сам является предметом
  проверки.
- Один элемент — один локатор в одном месте. Дублирование селектора по файлам превращает редизайн в
  многочасовую правку.
- Локатор, который находит несколько элементов, — скрытая ошибка: тест проверит первый попавшийся.

## Page object

Страница описывается объектом: локаторы внутри, наружу торчат действия на языке предметной области.

Тест говорит «войти под пользователем» и «оформить заказ», а не «найти поле, ввести текст, нажать
кнопку». При смене вёрстки правится один объект, тесты не трогаются.

Границы применимости:

- объект описывает страницу или крупный компонент, а не каждую кнопку;
- в объекте нет проверок — они остаются в тесте, иначе непонятно, что именно упало;
- объект не хранит состояние между тестами.

Для набора из десятка сценариев page object окупается. Для трёх скриптов — нет, и его отсутствие не
дефект.

## Частые ошибки

- Локаторы по сгенерированным классам: набор ломается на первом же деплое.
- Один и тот же селектор скопирован в десять файлов.
- Проверки внутри page object: тест падает с сообщением из недр объекта.
- Локатор, совпадающий с несколькими элементами — тест зелёный, проверяет не то.

## Проверка

- Ни один локатор не опирается на сгенерированные классы.
- Каждый локатор определён в одном месте.
- Проверено, что локатор находит ровно один элемент.
- После правки вёрстки набор чинится изменением объектов, а не тестов.
