# Автоматизация

Автотесты решают две задачи: повторяемый регресс и объективные доказательства. Вторая на разовых
заказах важнее первой — скрипт превращает «мне кажется, нет реакции на наведение» в замер, который
нельзя оспорить.

- [Пирамида тестирования](test-pyramid.md) — что автоматизировать и на каком уровне.
- [Playwright](playwright.md) — основной инструмент.
- [Локаторы и page object](locators-and-page-objects.md) — как сделать тесты устойчивыми.
- [Флаки-тесты](flaky-tests.md) — почему тест падает через раз и что с этим делать.
- [Сбор доказательств](evidence-collection.md) — автоматизация как источник фактов для баг-репортов.

## Автоматизация на разовом заказе

Полноценный автотестовый набор при разовой проверке сайта не окупается: его писать дольше, чем
проверить руками. Окупается другое — короткие скрипты для добычи фактов:

- сравнение вычисленных стилей до и после наведения;
- обход всех ссылок с проверкой кода ответа;
- проверка отсутствия горизонтальной прокрутки на наборе ширин;
- перехват запроса формы и чтение ответа сервера;
- сбор ошибок консоли по всем страницам.

Каждый такой скрипт пишется за минуты и даёт доказательство, которое разработчик не оспорит.

## Когда набор окупается

- Проект на поддержке: регресс повторяется каждый релиз.
- Много однотипных проверок: каталог, формы, локализации.
- Требуется прогон на нескольких браузерах.

## Кросс-рантайм

Скрипты запускаются из командной строки и не зависят от того, работает агент в Claude Code или в
Codex. MCP-браузер — необязательный ускоритель для разведки, но обязательные шаги пайплайна на нём не
строятся, см. [систему скиллов](../00-start-here/skill-system.md).
