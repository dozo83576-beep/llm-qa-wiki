# Playwright

Основной инструмент браузерной автоматизации. Выбран потому, что работает одинаково из Node и Python,
запускается из командной строки без привязки к рантайму агента и умеет отдавать трассировку, видео и
сетевые ответы для доказательств.

## Когда использовать

- Добыча фактов для баг-репортов на разовом заказе.
- Регрессионный набор на проекте поддержки.
- Прогон одного сценария на нескольких браузерах.
- Проверки, недостижимые вручную: обход сотни ссылок, замер стилей, перехват запросов.

## Когда не использовать

- Проверка бизнес-логики, которую дешевле покрыть unit-тестами.
- Разовая проверка одной формы: открыть браузер и проверить руками быстрее.
- Нагрузочное тестирование — для него [другие инструменты](../10-performance/tools.md).

## Что даёт для доказательств

Ключевая ценность на заказе — объективные факты:

- **Вычисленные стили** до и после действия: доказательство отсутствия реакции на наведение.
  См. [паттерн](../../patterns/ui/computed-style-hover-proof.md).
- **Перехват запросов**: что ушло на сервер и что вернулось при отправке формы.
- **Ошибки консоли** собираются автоматически по всем страницам.
- **Трассировка, видео, скриншот** на падении.
- **Состояние DOM**: видимость элемента, значение атрибутов, результат `validity` у полей формы.

## Практика

- **Ожидание состояния, а не времени.** Фиксированная пауза — главный источник
  [флаки](flaky-tests.md). Ждать нужно появления элемента или ответа сети.
- **Устойчивые локаторы**: по роли и доступному имени либо по тестовому идентификатору, не по
  цепочке CSS-классов. См. [локаторы](locators-and-page-objects.md).
- **Изоляция теста.** Каждый тест сам готовит данные и не зависит от порядка выполнения.
- **Состояние авторизации** сохраняется один раз и переиспользуется, а не проходится в каждом тесте.
- **Скриншот только при провале.** Снимок каждого шага раздувает артефакты и ничего не доказывает.
- **Уникальные данные** через отметку времени: иначе повторный прогон падает на уже существующем
  email.

## Частые ошибки

- Пауза фиксированной длительности вместо ожидания состояния.
- Локаторы по сгенерированным классам: ломаются на следующем деплое.
- Тесты, зависящие от данных, созданных другим тестом.
- Прогон против продакшена с изменяющими действиями.
- Скриншоты и трассировки с реальными персональными данными или токенами — они уходят в отчёт.

## Проверка

- Ни один сценарий не содержит фиксированных пауз.
- Прогон повторно даёт тот же результат.
- Тесты проходят при запуске в произвольном порядке.
- Артефакты не содержат персональных данных и учётных данных.
- Скрипт запускается из командной строки и не требует конкретного агента.
