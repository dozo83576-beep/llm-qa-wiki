# Сбор доказательств

Доказательство превращает наблюдение в факт. Разница между «нет реакции на наведение» и «вычисленные
стили до и после наведения совпадают полностью» — это разница между спором и исправленным дефектом.

## Когда использовать

- Любой дефект, не следующий буквально из ТЗ.
- Любое замечание, опирающееся на норму, а не на требование.
- Дефект, который заказчик или разработчик уже однажды оспорил.

## Когда не использовать

- Очевидное расхождение с явным требованием: ТЗ говорит «кнопка «Купить»», на странице «Заказать».
  Достаточно ссылки на пункт ТЗ.

## Иерархия доказательств

От сильного к слабому:

1. **Машинный замер.** Вычисленные стили, коды ответов, тело ответа сервера, результат проверки
   валидности поля. Не зависит от интерпретации.
2. **Запись экрана.** Показывает динамику: что нажали, что произошло. Незаменима для плавающих
   дефектов и сценариев из нескольких шагов.
3. **Скриншот.** Годится для статичного расхождения: вёрстка, текст, состояние элемента.
4. **Текстовое описание.** Само по себе доказательством не является.

Для дефектов, где спор вероятен, берётся первый уровень. Замер стилей до и после действия — типовой
приём, см. [паттерн](../../patterns/ui/computed-style-hover-proof.md).

## Правила

- **Снимок на каждый кейс.** Заказчики просят показать реакцию системы на действия пользователя, а
  не только поломки. `Pass` без доказательства — утверждение без подтверждения: проверить его можно
  лишь на слово. Снимать каждый шаг внутри кейса при этом не нужно — достаточно кадра с итоговым
  состоянием.
- **Имя файла начинается с Case ID**: `TC-001.png`. Кадров на кейс может быть несколько —
  `TC-001-2-hover.png`, `TC-007_hint.png`; разделитель после идентификатора любой. Связь с отчётом
  тогда восстанавливается без пояснений, а проверка делает это механически.
- **Файлы, не привязанные к кейсу, с `TC-` не начинаются.** Журналы прогона, замеры, снимки
  разведки — `run-journal.json`, `_recon-home.png`. Иначе проверка сочтёт их снимком
  несуществующего кейса.
- **Показывать, куда смотреть.** Снимок всей страницы без выделения области заставляет разработчика
  искать проблему.
- **Фиксировать контекст.** В кадре или рядом: URL, разрешение, состояние авторизации.

## Передача в отчёт

В формате поставки доказательства идут **ссылками** в колонке `Attachments/Links`, а не вложенными
картинками. Причины: файл остаётся лёгким, ссылка открывается в один клик, запись экрана вложить в
таблицу невозможно. См. [спецификацию](../14-templates/xlsx-test-management.md).

Хранилище ссылок согласуется с заказчиком до начала работ. Ссылка должна пережить срок разбора
дефектов.

## Приватность

Записи и скриншоты уходят наружу — заказчику, в переписку, иногда третьим лицам:

- не попадают в кадр: реальные персональные данные, номера карт, токены, пароли, содержимое чужих
  аккаунтов;
- тестовые данные генерируются заведомо ненастоящими;
- если дефект воспроизводится только на реальных данных, чувствительная часть закрывается до
  публикации.

## Частые ошибки

- Скриншот вместо записи для дефекта, проявляющегося в динамике.
- Доказательство, снятое после перезагрузки: состояния, при котором проявился дефект, уже нет.
- Ссылки с ограниченным сроком жизни — через месяц отчёт пустой.
- Персональные данные в кадре.

## Проверка

- У каждого дефекта есть доказательство подходящего уровня.
- Имена файлов соответствуют идентификаторам дефектов.
- Ссылки открываются из отчёта и не имеют срока истечения.
- Ни на одном доказательстве нет персональных данных и учётных данных.
