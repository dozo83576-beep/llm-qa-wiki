# Оракул и границы тестирования

Оракул — источник, из которого берётся ожидаемый результат. Без него проверка невозможна: нельзя
сказать «неправильно», не имея эталона «правильно». На заказах без ТЗ выбор оракула — первое решение,
которое приходится принимать.

## Когда использовать

- Заказчик прислал ссылку на сайт и просит «протестировать» — требований нет.
- Требования есть, но не покрывают найденное поведение.
- Спор с разработчиком «это не баг, это так задумано».

## Когда не использовать

- Когда есть однозначное ТЗ и поведение прямо ему противоречит. Оракул уже определён.

## Иерархия оракулов

Применять сверху вниз, первый доступный выигрывает:

1. **Явные требования** — ТЗ, спецификация API, макет. Самый сильный оракул: расхождение бесспорно.
2. **Согласованный стандарт** — WCAG для доступности, платёжные правила, гайдлайны платформы для
   мобильных приложений.
3. **Внутренняя согласованность** — на одной странице кнопка реагирует на наведение, на другой такая
   же нет. Продукт противоречит сам себе, и это доказуемо без ТЗ.
4. **Отраслевая норма** — логотип ведёт на главную, поиск справа вверху, поля обязательные помечены.
   Опора: [чек-лист UX](../../checklists/ux-experience.md).
5. **Здравый смысл пользователя** — самый слабый. Годится для замечаний, не для дефектов уровня
   `Major`.

Чем ниже уровень, тем тщательнее нужно доказательство: скриншот, запись, замер, ссылка на источник
нормы.

## Границы

Исчерпывающее тестирование невозможно, поэтому границы фиксируются письменно:

- что тестируется — страницы, сценарии, роли;
- на чём — браузеры, устройства, разрешения;
- что не тестируется и почему — нет доступа, вне договора, отдельный этап.

Незафиксированная граница всегда трактуется заказчиком в свою пользу.

## Частые ошибки

- Дефект с ожидаемым результатом «должно быть удобно». Не воспроизводится, не чинится, не
  засчитывается.
- Проверка по личному вкусу вместо нормы. Оракул уровня 5 без ссылки — повод для спора.
- Умолчание о том, что осталось за скоупом. После релиза непроверенная область оказывается вашей
  зоной ответственности.

## Проверка

- У каждого тест-кейса ожидаемый результат измерим: конкретный URL, текст сообщения, код ответа,
  видимое изменение.
- Для каждого дефекта уровня 3–5 приложено доказательство или ссылка на норму.
- В `_qa-intake.md` есть раздел «вне скоупа».
