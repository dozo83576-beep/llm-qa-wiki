# Метрики производительности

Что измерять и как читать результат. Главная ошибка области — среднее время ответа: оно скрывает
именно тех пользователей, ради которых проводился замер.

## Когда использовать

- Формулировка требований к скорости в тест-плане.
- Интерпретация результата нагрузочного прогона.
- Обоснование замечания по скорости числами.

## Когда не использовать

- Как самоцель. Улучшение метрики, не влияющее на пользователя, не стоит потраченного времени.

## Перцентили вместо среднего

Среднее время ответа маскирует хвост. При среднем 800 мс каждый двадцатый пользователь может ждать
8 секунд — и именно он уйдёт.

Читать нужно перцентили:

- **p50** — типичный пользователь;
- **p95** — то, что чувствует заметная доля;
- **p99** — худший практический случай.

Требование формулируется через перцентиль: «p95 времени ответа не превышает 3 с при 100
одновременных пользователях».

## Метрики нагрузки

- **Время ответа** по перцентилям, отдельно по сценариям: каталог и оплата ведут себя по-разному.
- **Пропускная способность** — запросов в секунду.
- **Доля ошибок** — под нагрузкой должна оставаться в согласованных пределах; рост доли ошибок
  раньше роста времени ответа означает, что система отбрасывает запросы.
- **Использование ресурсов** — процессор, память, соединения с базой. Показывает, что именно упёрлось.

## Метрики загрузки страницы

Пользовательские метрики загрузки:

- **LCP** — момент отрисовки основного содержимого. Отвечает на вопрос «когда стало видно нужное».
- **INP** — задержка отклика на действия пользователя.
- **CLS** — смещение раскладки после загрузки: кнопка уезжает в момент нажатия.

Замер делается на реальных условиях: мобильное устройство, медленный канал, холодный кэш. Замер на
офисном Wi-Fi с прогретым кэшем показывает результат, которого не увидит ни один пользователь.

## Как формулировать замечание

Плохо: «сайт медленно грузится».

Хорошо: «главная: LCP 5,8 с на профиле 4G с холодным кэшем при целевом значении до 2,5 с. Основной
вклад — изображение шапки 3,8 МБ без сжатия и без адаптивных размеров».

## Частые ошибки

- Отчёт по среднему времени ответа.
- Замер на быстром канале с прогретым кэшем.
- Метрики без указания уровня нагрузки, при котором сняты.
- Игнорирование доли ошибок: время ответа отличное, потому что половина запросов отброшена.
- Замер одного прогона: нужны повторы, иначе результат случаен.

## Проверка

- Требования сформулированы через перцентили и уровень нагрузки.
- Замеры сняты на реальном профиле сети и устройства.
- Приведена доля ошибок вместе со временем ответа.
- Результат получен не менее чем на трёх прогонах.
- Каждое замечание содержит число, цель и основной вклад.
