# Производительность

Две разные задачи под одним словом: скорость загрузки для одного пользователя и поведение системы под
нагрузкой. Первая нужна почти всегда, вторая — редко и только по согласованию.

- [Виды нагрузочного тестирования](load-types.md) — что именно проверяем.
- [Метрики](metrics.md) — что измеряем и какие числа считать нормой.
- [Инструменты](tools.md) — чем измеряем.

## Скорость загрузки

Доступна на любом заказе, не требует согласования, даёт измеримые замечания. Проверяется на реальных
страницах в реальных условиях: медленный канал, мобильное устройство, холодный кэш.

Типовые находки: несжатые изображения, блокирующие скрипты, отсутствие кэширования, тяжёлые шрифты.
Каждая формулируется с числом: «главная грузится 6,2 с на 4G, из них 4,1 с — изображение шапки
размером 3,8 МБ».

## Нагрузочное тестирование

Требует отдельного разговора до начала:

- **письменное разрешение владельца** — нагрузка на чужую систему без согласования недопустима;
- **отдельный стенд**. Нагрузка на продакшен роняет реальный сервис и мешает реальным пользователям;
- **окно времени**, согласованное с хостингом: у провайдера могут быть свои ограничения;
- **профиль нагрузки** из реальных данных, а не выдуманный.

Без этих четырёх пунктов нагрузочное тестирование не начинается.

## Когда это обязательно

- Ожидается пиковый трафик: распродажа, реклама, сезон.
- Каталог с большим числом записей и сложными фильтрами.
- Оплата: отказ под нагрузкой стоит денег напрямую.
- Заказчик формулирует требование к времени ответа.

## Когда достаточно замера скорости

- Лендинг, сайт-визитка, блог.
- Внутренняя система на десяток пользователей.
