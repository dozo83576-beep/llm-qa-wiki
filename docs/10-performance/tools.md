# Инструменты замера

Чем измерять скорость и нагрузку. Выбор определяется задачей: замер одной страницы и нагрузка на
сервис требуют разных инструментов.

## Когда использовать

- Нужно подкрепить замечание по скорости числом.
- Согласовано нагрузочное тестирование.

## Когда не использовать

- Инструмент нагрузки для замера скорости страницы: он не выполняет JavaScript и не покажет
  пользовательские метрики.
- Браузерный аудит для оценки нагрузки: он измеряет одного пользователя.

## Замер загрузки страницы

**Аудит в браузере** (Lighthouse в составе Chrome DevTools) — быстрый старт. Даёт LCP, CLS, список
узких мест. Ограничения: результат зависит от машины и загрузки процессора, поэтому запускать нужно
несколько раз и брать медиану.

**Панель сети** — источник конкретики: размеры ресурсов, время каждого запроса, порядок загрузки.
Именно отсюда берётся формулировка «изображение 3,8 МБ», см.
[DevTools](../06-web-testing/devtools-console-network.md).

**Профиль сети и процессора.** Замер обязательно делается с ограничением скорости и замедлением
процессора — иначе результат не имеет отношения к мобильному пользователю.

## Нагрузочные инструменты

**k6** — сценарии на JavaScript, запуск из командной строки, хорошо ложится в CI. Подходит для
проверки API и типовых пользовательских путей. Порог входа низкий, если сценарии уже написаны на
JavaScript.

**JMeter** — графический интерфейс, богатый набор протоколов помимо HTTP, длинная история и много
готовых материалов. Тяжелее в автоматизации, но привычен многим командам и часто прямо назван в
требованиях заказчика.

Оба измеряют серверную часть. Ни один не отражает реальное время отрисовки в браузере: они не
выполняют клиентский код. Для полной картины нужны оба замера — серверный и браузерный.

## Практика

- Сценарий нагрузки повторяет реальный путь, а не бьёт в одну ручку.
- Пользовательские паузы между действиями обязательны.
- Прогон запускается не с той же машины, где стоит система: сеть и ресурсы исказят результат.
- Результаты сохраняются вместе с профилем и версией системы — иначе сравнивать не с чем.

## Частые ошибки

- Один запуск аудита и вывод по нему: разброс между запусками бывает кратным.
- Замер без ограничения сети и процессора.
- Нагрузка с ноутбука тестировщика через домашний канал: упирается канал, а не система.
- Сравнение замеров, снятых в разных условиях.

## Проверка

- Замер повторён не менее трёх раз, взята медиана.
- Указаны профиль сети, устройство и состояние кэша.
- Нагрузка подавалась не с той же машины, где работает система.
- Условия замера сохранены вместе с результатом.
