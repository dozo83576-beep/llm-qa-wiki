# Безопасность для тестировщика

Базовые проверки, доступные без специальной квалификации. Дают наибольшую отдачу на единицу времени и
находят дефекты, которые не видны через интерфейс.

## Когда использовать

- Есть авторизация, роли, оплата или персональные данные.
- Получено письменное разрешение владельца системы.

## Когда не использовать

- **Без письменного разрешения.** Разрешение фиксирует владельца, границы, окно времени и допустимые
  действия.
- На продакшене с реальными пользовательскими данными.
- Когда требуется глубокое тестирование на проникновение — это отдельная квалификация и отдельный
  договор.

## Что проверять

**Разграничение доступа** — самая результативная группа, см.
[негативные проверки API](../08-api-testing/api-negative-and-security.md):

- чужой объект по прямому идентификатору;
- действие без прав в обход скрытой кнопки;
- запрос без аутентификации;
- действие старым токеном после выхода.

**Серверная валидация.** Клиентская защита обходится за секунды. Всё, что отклоняет браузер, должно
отклоняться и сервером.

**Утечки в ответах и на страницах.** Трассировка стека, SQL-запрос, путь к файлу, версия ПО в
заголовках, чужие персональные данные в списках.

**Передача данных.** Соединение защищено, страницы с формами не отдаются по незащищённому протоколу.
Пароли и персональные данные не уходят в параметрах URL: они попадают в логи и историю.

**Аутентификация.** Ограничение частоты попыток входа. Сессия завершается при выходе. Восстановление
пароля не сообщает, существует ли учётная запись. Смена пароля завершает другие сессии.

**Загрузка файлов.** Проверка типа на сервере, а не по расширению. Ограничение размера. Загруженный
файл не исполняется на сервере и не отдаётся с опасным типом содержимого.

**Ввод, попадающий в вывод.** Специальные символы в полях, которые отображаются другим пользователям.
Фиксируется факт того, что ввод интерпретируется, дальше эксплуатация не идёт.

## Правила поведения

- Подтверждать факт минимальным действием и останавливаться.
- Не выгружать чужие данные «для доказательства» — достаточно снимка одного экрана с закрытой
  чувствительной частью.
- Критичное сообщать заказчику немедленно и приватно, а не в общем отчёте.
- Не оставлять созданные в ходе проверок объекты.

## Частые ошибки

- Проверки без разрешения.
- Эксплуатация найденного вместо фиксации.
- Публикация деталей уязвимости в общедоступном отчёте до исправления.
- Вывод «безопасность в порядке» по результатам базовых проверок: они не заменяют аудит.

## Проверка

- Есть письменное разрешение с границами и окном времени.
- Для каждой роли проверен доступ к чужому объекту.
- Серверная валидация проверена в обход клиентской.
- Проверено ограничение частоты попыток входа.
- Найденные критичные проблемы переданы приватно.
- Формулировка вывода не утверждает общую защищённость.
