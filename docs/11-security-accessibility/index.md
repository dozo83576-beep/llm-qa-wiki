# Безопасность и доступность

Две области, объединённые общим свойством: обе легко пропустить и обе дорого стоят после релиза —
утечка данных и недоступный сервис имеют юридические последствия.

- [Безопасность для тестировщика](security-basics.md) — что можно проверить без специальных навыков
  и без нарушения границ.
- [Доступность и WCAG](accessibility-wcag.md) — критерии и способы проверки.
- [Персональные данные](personal-data.md) — обращение с данными в ходе тестирования.

## Границы

**Безопасность.** Тестировщик общего профиля проверяет базовые вещи: разграничение доступа, серверную
валидацию, утечки в ответах, передачу данных. Глубокое тестирование на проникновение — отдельная
квалификация и отдельный договор.

**Без письменного разрешения security-проверки не проводятся.** Разрешение фиксирует владельца,
границы, окно времени и допустимые действия. Это не формальность: несогласованные действия с чужой
системой выходят за рамки тестирования.

**Найденное фиксируется, но не эксплуатируется.** Обнаружив доступ к чужим данным, тестировщик
подтверждает факт минимальным действием и останавливается. Выгрузка чужих данных «для доказательства»
недопустима.

**Доступность.** Проверяется на соответствие WCAG. Автоматические проверки ловят часть нарушений;
контраст, навигацию с клавиатуры и осмысленность альтернативных описаний нужно проверять вручную.

## Когда это обязательно

| Область | Обязательно, если |
|---|---|
| Безопасность | есть личный кабинет, оплата, персональные данные |
| Доступность | госуслуги, медицина, образование, крупный публичный сервис |
| Персональные данные | тестирование затрагивает реальные данные пользователей |

## Правило по умолчанию

Реальные персональные данные в тестировании не используются и наружу не уходят. Подробнее —
[персональные данные](personal-data.md).
