# Доступность и WCAG

Возможность пользоваться продуктом людям с ограничениями зрения, слуха, моторики. Регулируется WCAG;
целевой уровень для большинства проектов — AA.

## Когда использовать

- Госуслуги, медицина, образование, банки — часто обязательно по требованиям.
- Крупный публичный сервис.
- Заказчик заявил соответствие WCAG.

## Когда не использовать

- Как повод переделать дизайн целиком без запроса. Замечания фиксируются, приоритет расставляет
  заказчик.

## Что проверять вручную

Автоматические инструменты ловят меньшей части нарушений. Остальное — руками.

**Клавиатура.** Весь сценарий проходится без мыши:

- фокус виден всегда и не пропадает;
- порядок обхода соответствует визуальному;
- нет ловушек фокуса: из модального окна можно выйти;
- модальное окно забирает фокус при открытии и возвращает при закрытии;
- всё, что кликается мышью, доступно с клавиатуры.

**Контраст.** Обычный текст — не менее 4.5:1 к фону, крупный — 3:1, интерактивные элементы и границы
полей — 3:1. Проверяется замером, а не на глаз. Отдельно проверяются состояния `hover` и `focus` —
там контраст часто падает.

**Изображения.** Содержательные имеют осмысленное альтернативное описание; декоративные — пустое.
Описание «изображение» или имя файла нарушением не устраняется.

**Формы.** У каждого поля есть связанная подпись, а не только подсказка внутри. Ошибка сообщается
текстом, а не только цветом рамки. Обязательность обозначена не только звёздочкой-цветом.

**Структура.** Один `h1` на страницу, заголовки без пропуска уровней. Есть возможность пропустить
навигацию. Язык страницы объявлен.

**Цвет как единственный носитель смысла.** Статус, обозначенный только красным или зелёным, не
считывается при дальтонизме.

**Движение.** Автовоспроизведение можно остановить. Анимация уважает системную настройку уменьшения
движения.

## Как проверять

- Автоматический аудит — первым проходом, чтобы снять очевидное.
- Навигация с клавиатуры — обязательно вручную.
- Замер контраста инструментом; результат приводится числом: «3.1:1 при требуемых 4.5:1».
- Проверка со скринридером — по возможности; хотя бы на ключевом сценарии.

Косвенная проверка: если элемент не находится автотестом по роли и доступному имени, его не найдёт и
скринридер, см. [локаторы](../09-automation/locators-and-page-objects.md).

## Частые ошибки

- Вывод о доступности по результату автоматического аудита.
- Оценка контраста на глаз.
- Пропуск состояний `hover` и `focus` при замере контраста.
- Альтернативное описание, дублирующее подпись под изображением.
- Проверка клавиатурной навигации только на главной.

## Проверка

- Ключевой сценарий пройден полностью с клавиатуры.
- Контраст замерен инструментом, включая состояния элементов.
- Все содержательные изображения имеют осмысленные описания.
- Ошибки форм передаются текстом, а не только цветом.
- Каждое замечание содержит номер критерия WCAG и замеренное значение.
