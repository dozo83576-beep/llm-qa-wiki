# Персональные данные в тестировании

Тестирование постоянно соприкасается с персональными данными: тестовые аккаунты, выгрузки из
продакшена, скриншоты личных кабинетов, записи экрана. Каждый из этих артефактов уходит наружу — в
отчёт, в переписку, в облачный сервис.

## Когда использовать

- Заказ затрагивает личные кабинеты, заявки, платежи, медицинские или образовательные данные.
- Заказчик передал выгрузку из рабочей системы для тестирования.
- Артефакты тестирования отправляются наружу.

## Когда не использовать

- Полностью статический сайт без форм и без пользователей.

## Правила

**Реальные данные не используются.** Тестовые данные генерируются заведомо ненастоящими: домен
`example.com`, номера телефонов из зарезервированных диапазонов, вымышленные имена. Данные, похожие на
настоящие, попадают в рассылки и звонки реальным людям.

**Выгрузка из продакшена обезличивается до передачи.** Если заказчик прислал такую выгрузку без
обезличивания — это повод сказать об этом, а не молча начать работу.

**Артефакты чистятся перед отправкой.** Скриншоты и записи не содержат: реальных имён, телефонов,
адресов, номеров карт, паспортных данных, токенов, паролей, содержимого чужих аккаунтов. Если дефект
воспроизводится только на реальных данных, чувствительная часть закрывается.

**Ничего лишнего в облачные сервисы.** Перед отправкой файла во внешний сервис — хранилище записей,
конвертер, ИИ-помощник — проверка: есть ли там персональные данные, есть ли коммерческая тайна,
показали бы вы это конкуренту или проверяющему. Хотя бы одно «да» — не отправлять.

**Учётные данные не попадают в отчёт.** Ни в текст дефекта, ни на скриншот, ни в код автотеста. Для
автотестов — переменные окружения, а не значения в файлах.

**Созданное убирается.** Тестовые аккаунты, заказы и записи удаляются после завершения работ либо
передаются заказчику списком для удаления.

## Обезличивание

Замена, а не удаление: структура и длина данных сохраняются, иначе меняется поведение системы.
Фамилия заменяется на фамилию, номер телефона — на номер того же формата. Связи между записями
сохраняются, чтобы сценарии оставались проходимыми.

Обратимое «обезличивание» вроде сдвига всех дат на одно число обезличиванием не является.

## Частые ошибки

- Регистрация тестового аккаунта на личную почту или реальный телефон.
- Скриншот личного кабинета реального пользователя в баг-репорте.
- Загрузка выгрузки с данными клиентов в облачный сервис для удобства.
- Учётные данные тестового аккаунта в теле дефекта.
- Тестовые заказы, оставшиеся в системе после сдачи.

## Проверка

- Все тестовые данные заведомо ненастоящие.
- Артефакты просмотрены на предмет персональных данных перед отправкой.
- Ни один файл с реальными данными не уходил во внешние сервисы.
- Учётные данные отсутствуют в отчёте и в коде.
- Созданные тестовые объекты удалены или переданы списком.
