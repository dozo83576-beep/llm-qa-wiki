# UI-тестирование

Проверка интерфейса на соответствие макетам, фирменному стилю и стандартам платформы. Отвечает на
вопрос «выглядит и ведёт себя так, как задумано», в отличие от [UX](ux-usability-testing.md),
который отвечает «удобно ли пользователю».

## Когда использовать

- Есть макеты — сверка обязательна.
- Есть брендбук: цвета, шрифты, логотип.
- Продукт под конкретную платформу с гайдлайнами.

## Когда не использовать

- Макетов нет и брендбука нет. Тогда остаётся внутренняя согласованность и отраслевая норма — это
  уже [UX](ux-usability-testing.md), и оформляется иначе.

## Что проверять

**Соответствие макету.** Положение элементов, размеры, отступы между блоками. Расхождение фиксируется
с указанием величины: «отступ 16 px вместо 24 px по макету», а не «съехало».

**Типографика.** Читаемость на основном фоне и на плашках. Явная иерархия заголовков: h1 крупнее h2.
Не более двух-трёх шрифтовых семейств. Заголовки не заканчиваются точкой. Капс не используется для
основного текста.

**Состояния элементов.** Самая пропускаемая часть:

- `hover` — визуальная реакция на наведение у всех кликабельных элементов;
- `focus` — видимый фокус при навигации с клавиатуры;
- `active`, `disabled` — отключённый элемент показан, а не спрятан, и объясняет причину;
- `visited` для ссылок; курсор меняется на `pointer` над кликабельным.

Отсутствие `hover` у элементов шапки — типовой дефект: элемент выглядит кликабельным, но не
подтверждает это. Ловится сравнением вычисленных стилей до и после наведения, см.
[паттерн](../../patterns/ui/computed-style-hover-proof.md).

**Адаптивность.** Ключевые разрешения, портретная и альбомная ориентация, отсутствие
горизонтальной прокрутки.

**Поля и стандартные элементы.** Поведение при длинном значении, при некорректном вводе, вид
чекбоксов, радиокнопок, полей для номера карты.

**Информирующие элементы.** Вид и место сообщений об ошибках, уведомлений, подсказок.

## Частые ошибки

- Проверка только «в покое», без состояний. Половина UI-дефектов живёт в `hover` и `focus`.
- Дефект «криво выглядит» без замера и скриншота — не воспроизводится и не чинится.
- Сверка с макетом при другом масштабе браузера: отличия окажутся мнимыми.
- Пропуск орфографии. Опечатка в интерфейсе бьёт по доверию сильнее, чем смещение на 4 px.

## Проверка

- Для каждого кликабельного элемента проверены `hover` и `focus`.
- Расхождения с макетом описаны числами.
- Проверены минимум три разрешения, включая 360 px.
- Текст интерфейса вычитан на орфографию.
