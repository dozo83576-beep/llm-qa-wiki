# Попарное тестирование

Способ сжать комбинаторный взрыв. Основан на наблюдении: большинство дефектов вызывается одним
параметром или взаимодействием двух, а не редкой комбинацией пяти. Достаточно покрыть все пары
значений, а не все сочетания.

## Когда использовать

- Фильтры каталога: категория, цена, наличие, бренд, сортировка.
- Настройки с независимыми переключателями.
- Матрица сред: браузер × ОС × разрешение × язык.
- Формы, где несколько выпадающих списков влияют на результат.

## Когда не использовать

- Параметры связаны бизнес-правилом — тогда нужны
  [таблицы решений](decision-table-testing.md), иначе получатся невозможные комбинации.
- Параметров два-три с малым числом значений: полный перебор дешевле и надёжнее.
- Критичная функциональность вроде расчёта платежа — там комбинации проверяются полностью.

## Как это делается

Пять фильтров по три значения дают 243 комбинации. Попарное покрытие требует около 9–13.

Пример на четырёх параметрах по два значения (16 комбинаций → 5):

| № | Категория | Наличие | Цена | Сортировка |
|---|---|---|---|---|
| 1 | Обувь | В наличии | По возрастанию | По цене |
| 2 | Обувь | Под заказ | По убыванию | По новизне |
| 3 | Одежда | В наличии | По убыванию | По новизне |
| 4 | Одежда | Под заказ | По возрастанию | По цене |
| 5 | Одежда | В наличии | По возрастанию | По новизне |

Каждая пара значений любых двух параметров встречается хотя бы раз.

Наборы строятся инструментом, а не вручную: ручная сборка почти всегда даёт пробелы. Подойдёт любой
генератор попарных наборов; результат сохраняется в `_qa-cases.md`, чтобы прогон был воспроизводим.

## Практика

- Значения параметров сначала сокращаются
  [эквивалентными классами](equivalence-partitioning.md): не все цены, а «есть результат» и «нет
  результата».
- Невозможные комбинации исключаются до генерации, иначе часть набора уйдёт в мусор.
- К попарному набору добавляются вручную: комбинация из реального инцидента и комбинация, дающая
  пустую выдачу.

## Частые ошибки

- Применение к связанным параметрам: получаются комбинации, которые система обязана отклонять, и
  прогон превращается в проверку валидации.
- Использование там, где нужен полный перебор: расчёт скидки, права доступа.
- Набор, собранный на глаз: покрытие пар не проверено, техника не применена по существу.
- Отсутствие зафиксированного набора — повторить прогон невозможно.

## Проверка

- Сгенерированный набор сохранён в артефакте кейсов.
- Невозможные комбинации исключены до генерации.
- К набору добавлены пустая выдача и комбинация из прошлого инцидента.
- Для критичной логики попарное не применялось — там полный перебор.
