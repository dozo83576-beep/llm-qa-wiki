# Эквивалентные классы

Разбиение множества входных данных на группы, внутри которых система ведёт себя одинаково. Из каждой
группы берётся один представитель — этого достаточно, чтобы проверить поведение всей группы.

## Когда использовать

- Любое поле ввода: текст, число, дата, файл.
- Выбор из списка, где варианты обрабатываются по-разному.
- Роли пользователей с разными правами.

## Когда не использовать

- Когда внутри группы поведение всё-таки различается — тогда группа разбита неверно и её надо делить
  дальше.
- Для комбинаций нескольких полей: там нужны [таблицы решений](decision-table-testing.md) или
  [попарное](pairwise-testing.md).

## Как это делается

Для каждого поля выделяются валидные и невалидные классы. Невалидных почти всегда больше, и именно
там живут дефекты.

Поле «Возраст», допустимо целое от 18 до 99:

| Класс | Тип | Представитель |
|---|---|---|
| 18…99 | валидный | 35 |
| меньше 18 | невалидный | 10 |
| больше 99 | невалидный | 150 |
| не число | невалидный | `abc` |
| дробное | невалидный | `35.5` |
| отрицательное | невалидный | `-5` |
| пустое | невалидный | `` |
| пробелы | невалидный | `   ` |

Восемь кейсов вместо перебора всех чисел.

Поле «Email»: валидный формат; без `@`; без домена; с пробелом внутри; кириллица в домене; длиннее
максимума; уже зарегистрированный.

**Важно:** классы выделяются по поведению системы, а не по виду данных. Если система по-разному
обрабатывает `.ru` и `.com`, это два класса, хотя оба выглядят валидными email.

## Практика

Классы для одного поля дают базовый набор. Дальше:

- добавить [граничные значения](boundary-value-analysis.md) на краях валидного класса;
- проверить, что невалидный класс даёт понятное сообщение, а не общее «Ошибка»;
- для строк отдельно проверить спецсимволы и пробелы по краям — их часто забывают обрезать.

## Частые ошибки

- Проверка нескольких представителей одного класса: три разных валидных email вместо одного. Время
  потрачено, покрытие не выросло.
- Пропуск невалидных классов: набор из одного happy path.
- Одна группа «невалидные данные» на всё: пустое поле, буквы в числовом и превышение длины
  обрабатываются разным кодом и ломаются по-разному.
- Класс «пустое значение» не выделен отдельно от «пробелы» — поведение почти всегда различается.

## Проверка

- Для каждого поля выписаны валидные и невалидные классы.
- Из каждого класса взят ровно один представитель.
- Каждый невалидный класс проверен на понятность сообщения об ошибке.
