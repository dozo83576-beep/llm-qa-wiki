# Граничные значения

Проверка краёв допустимого диапазона. Работает потому, что ошибки в коде концентрируются на
сравнениях: `>` вместо `>=`, `<` вместо `<=`, обрезание на единицу.

## Когда использовать

- Всегда вместе с [эквивалентными классами](equivalence-partitioning.md): классы дают середину,
  границы — края.
- Любое ограничение: длина строки, диапазон чисел, количество, размер файла, даты, число элементов
  на странице.

## Когда не использовать

- Данные без порядка: список городов, тип оплаты. Границы там не существуют, достаточно классов.

## Как это делается

Для каждой границы проверяются три значения: на границе, на единицу внутрь, на единицу наружу.

Пароль от 6 до 20 символов:

| Значение | Длина | Ожидание |
|---|---|---|
| `Ab1!x` | 5 | отклонён, сообщение о минимуме |
| `Ab1!xy` | 6 | принят |
| `Ab1!xyz` | 7 | принят |
| 19 символов | 19 | принят |
| 20 символов | 20 | принят |
| 21 символ | 21 | отклонён, сообщение о максимуме |

Шесть кейсов вместо перебора длин.

## Границы, которые забывают

- **Ноль и пустота.** Количество товара `0`, пустая корзина, поиск по пустой строке, список без
  элементов.
- **Единица.** Один элемент в списке — часто ломается склонение и раскладка.
- **Переход через разряд.** 9 → 10, 99 → 100, 999 → 1000: ломается форматирование и ширина колонки.
- **Даты.** Последний день месяца, 29 февраля, переход через год, начало и конец рабочего дня.
- **Размер файла** ровно на пороге и на байт больше.
- **Постраничная навигация.** Ровно страница элементов, страница плюс один, последняя страница.

## Практика

Проверять нужно и клиентскую, и серверную границу — они часто разные. Если поле в браузере
ограничено `maxlength`, значение большей длины стоит отправить в обход интерфейса: серверная проверка
нередко отсутствует, и это уже дефект безопасности данных, а не удобства.

Отдельно проверяется, что сообщение об ошибке называет конкретное ограничение: «минимум 6 символов»,
а не «неверный пароль».

## Частые ошибки

- Проверка только «сильно меньше» и «сильно больше» вместо самих границ. Off-by-one так не ловится.
- Проверка только нижней границы. Верхняя ломается не реже.
- Доверие клиентской валидации без проверки сервера.
- Пропуск нуля и пустого списка как «неинтересных» случаев.

## Проверка

- Для каждого ограничения есть кейсы на границу и на единицу в обе стороны.
- Проверены ноль, единица и переход через разряд там, где применимо.
- Ограничение проверено не только через интерфейс, но и в обход клиентской валидации.
- Сообщение об ошибке называет конкретный предел.
