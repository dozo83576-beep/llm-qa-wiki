# Предугадывание ошибок

Техника, опирающаяся на опыт: где системы ломаются обычно. Дополняет формальные техники, а не
заменяет их — формальный набор даёт покрытие, предугадывание добирает то, что покрытием не ловится.

## Когда использовать

- Поверх готового набора кейсов, когда основное покрытие уже есть.
- На объекте того же типа, что уже тестировался: типовые дефекты повторяются.
- При коротком сроке, когда полный набор построить некогда.

## Когда не использовать

- Как основную технику. Набор из одних догадок непроверяем и невоспроизводим другим человеком.
- Без записи результата. Найденное надо превращать в кейс, иначе оно теряется.

## Список догадок

Опыт формализуется в [таксономию дефектов](../../bug-taxonomy/index.md). Базовый набор для веба:

**Ввод.** Пробелы в начале и конце. Только пробелы. Вставка из Word с невидимыми символами. Эмодзи.
Кириллица там, где ждут латиницу. Очень длинная строка без пробелов — ломает вёрстку. HTML-теги в
текстовом поле. Ведущий ноль в номере. Разные разделители дробной части.

**Действия.** Двойной клик по кнопке отправки. Отправка формы дважды подряд. Нажатие «Назад» после
отправки. Обновление страницы на середине оплаты. Работа в двух вкладках одновременно. Долгое
бездействие и продолжение после истечения сессии.

**Данные.** Ноль. Пустой список. Один элемент. Очень много элементов. Удалённый объект, открытый по
старой ссылке. Объект, изменённый в другой вкладке.

**Среда.** Медленная сеть. Обрыв соединения на середине запроса. Отключённый JavaScript. Блокировщик
рекламы. Приватный режим браузера. Другой часовой пояс.

**Права.** Прямая ссылка на чужой объект. Действие после выхода из аккаунта. Действие ролью, у
которой нет прав, в обход скрытой кнопки.

## Практика

Двойной клик по кнопке отправки — источник дублей заявок и повторных списаний. Проверяется всегда,
где есть отправка формы или платёж.

Каждая сработавшая догадка оформляется дважды: как дефект и как пункт таксономии, чтобы на следующем
заказе проверка была не догадкой, а частью набора.

## Частые ошибки

- Подмена формального набора списком догадок: покрытие оказывается неизвестным.
- Догадки без записи — на следующем проекте всё сначала.
- Проверка экзотики при непокрытых базовых сценариях.
- Дефект от догадки без чётких шагов воспроизведения: «иногда дублируется» не чинится.

## Проверка

- Формальный набор построен до применения техники.
- Каждая сработавшая догадка превращена в кейс с воспроизводимыми шагами.
- Новые типовые дефекты внесены в таксономию.
