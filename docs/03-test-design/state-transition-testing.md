# Диаграммы состояний

Техника для объектов, у которых есть статус и правила перехода между статусами. Проверяются не только
разрешённые переходы, но и запрещённые — последние ломаются чаще.

## Когда использовать

- Заказ: создан → оплачен → собран → отправлен → доставлен → закрыт.
- Пользователь: не зарегистрирован → зарегистрирован → подтверждён → заблокирован.
- Корзина, сессия, подписка, заявка, документ на согласовании.

## Когда не использовать

- Поведение зависит только от текущего ввода, а не от предыстории. Тогда достаточно
  [таблиц решений](decision-table-testing.md).

## Как это делается

1. Выписать состояния.
2. Выписать события, меняющие состояние.
3. Построить таблицу переходов: состояние × событие → новое состояние либо «запрещено».
4. Покрыть каждый разрешённый переход и выборочно — запрещённые.

Заказ:

| Состояние \ Событие | Оплатить | Отменить | Отправить | Вернуть |
|---|---|---|---|---|
| Создан | Оплачен | Отменён | запрещено | запрещено |
| Оплачен | запрещено | Отменён (возврат) | Отправлен | запрещено |
| Отправлен | запрещено | запрещено | запрещено | Возврат |
| Отменён | запрещено | запрещено | запрещено | запрещено |

Каждая непустая ячейка — тест-кейс. Ячейки «запрещено» — тоже кейсы: система должна отклонить
действие, а не выполнить его молча.

## Как проверять запрещённые переходы

Через интерфейс запрещённый переход обычно недоступен: кнопки нет. Это не доказательство. Проверять
нужно в обход:

- отправить запрос напрямую в API с нужным действием;
- открыть страницу действия по прямой ссылке;
- выполнить действие в двух вкладках: в одной отменить заказ, в другой нажать «Оплатить» на уже
  отменённом.

Последний сценарий — источник самых дорогих дефектов: двойная оплата, отгрузка отменённого заказа.

## Частые ошибки

- Проверка только «счастливого» пути по цепочке состояний.
- Вывод «переход невозможен, кнопка скрыта» без проверки на уровне API.
- Пропуск устаревшего состояния вкладки: страница открыта давно, статус объекта успел измениться.
- Игнорирование конечных состояний: из «Отменён» не должно быть выхода никуда.

## Проверка

- Таблица переходов построена и согласована с заказчиком.
- Каждый разрешённый переход покрыт кейсом.
- Не менее одного запрещённого перехода на состояние проверено в обход интерфейса.
- Проверен сценарий с устаревшим состоянием страницы.
