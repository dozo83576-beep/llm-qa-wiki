# Система скиллов

Скиллы — тонкие роутеры. Вся инженерная глубина остаётся в вики, скилл лишь направляет в нужные
документы, чек-листы и playbooks и следит за тем, чтобы фаза закрылась артефактом.

## Пайплайн

Семь фаз, каждая со своим артефактом в каталоге проекта:

| Скилл | Артефакт | Что делает |
|---|---|---|
| `qa-intake` | `_qa-intake.md` | объект, окружение, доступы, границы скоупа, риски |
| `qa-plan` | `_qa-plan.md` | уровни и виды тестирования, entry/exit criteria, выбор чек-листов |
| `qa-design` | `_qa-cases.md` | тест-кейсы по техникам тест-дизайна, покрытие |
| `qa-execute` | `_qa-run.md` + `evidence/` | прогон и доказательства |
| `qa-defects` | `_qa-defects.md` | баг-репорты, severity, трассируемость Fail → BR |
| `qa-report` | `_qa-report.json` + XLSX | сборка отчёта и прогон валидатора |
| `qa-capture` | `_qa-learning-review.md` | фиксация опыта в вики |

Оркестратор `run-qa-project` ведёт по маршруту и умеет возобновлять работу: фаза считается закрытой,
когда её артефакт существует и непуст. Состояние живёт в файлах, а не в памяти агента.

Источник правды о фазах — `resources/qa-pipeline-contract.json`. Скиллы читают его, а не хардкодят
маршрут. Проверка состояния:

```
pwsh tools/verify-qa-pipeline.ps1 -ProjectRoot D:\Rabota\projects\<проект>
```

## Кросс-рантайм

Скиллы работают одинаково в Claude Code и Codex. Правила, которые это обеспечивают:

- `SKILL.md` — общий формат для обоих рантаймов.
- `agents/openai.yaml` — нужен Codex, безвреден для Claude Code.
- Ни один обязательный шаг пайплайна не опирается на MCP-сервер или инструмент конкретного рантайма.
  MCP-браузер и прочие помощники — необязательные ускорители.
- Исполняемая часть — Python и PowerShell, доступные обоим.

Канон скиллов — `agent-skills/`. Раскатка в оба рантайма:

```
pwsh agent-skills/sync-skills.ps1 -DryRun
```

## Когда не использовать пайплайн

- Разовая проверка одной формы. Откройте чек-лист и проверьте, отчёт формата Test Management здесь
  избыточен.
- Задача не про тестирование: правки вёрстки, консультация, оценка сроков.

## Частые ошибки

- Дублирование содержимого вики в скилл. Техники, чек-листы и спецификация отчёта живут в вики;
  скилл на них ссылается.
- Пропуск фазы «ради скорости». Кейсы без плана дают покрытие наугад, а отчёт без валидатора едет
  заказчику с битой трассируемостью.
- Правка скилла в `~/.claude/skills` или `~/.codex/skills` напрямую. Это рантайм-копии, их
  перезапишет следующая раскатка.

## Проверка

```
pwsh tools/verify-agent-skills.ps1 -VerifyUserRuntimes
```

Показывает расхождение канона с обеими рантайм-копиями. Расхождение поведения скилла между Claude
Code и Codex означает, что в него просочилась рантайм-зависимость.
