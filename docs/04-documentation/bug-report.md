# Баг-репорт

Описание дефекта, по которому его починят без дополнительных вопросов. Мера качества одна:
разработчик воспроизводит проблему с первого раза, не обращаясь к автору.

## Когда использовать

- Найдено расхождение фактического поведения с ожидаемым, подкреплённым
  [оракулом](../01-fundamentals/test-oracle-and-limits.md).

## Когда не использовать

- Замечание вкусового характера без опоры на норму — это рекомендация в отдельном разделе отчёта.
- Вопрос о неопределённом поведении — сначала уточнение у заказчика, потом дефект.

## Обязательные поля

Соответствуют листу `Bug Reports` [формата отчёта](../14-templates/xlsx-test-management.md):

- **Bug ID** — `BR-001`.
- **Title** — суть в одной строке: что и где сломано.
- **Related Case ID** — кейс, на котором обнаружено.
- **Session ID** — сессия прогона.
- **Preconditions** — состояние до воспроизведения.
- **Error Step** — шаг, на котором проявляется дефект.
- **Expected Result** — что должно было произойти, со ссылкой на источник ожидания.
- **Actual Result** — что произошло фактически.
- **Severity** — по [таксономии](../05-defect-management/severity-vs-priority.md).
- **Priority** — срочность исправления.
- **Environment** — браузер, версия, ОС, разрешение.
- **Attachments/Links** — доказательство.
- **Date Reported** — дата обнаружения.

## Правила

**Заголовок конкретен.** «Пункт «Проекты» ведёт на главную страницу» — годится. «Не работает меню» —
нет.

**Один дефект — один баг-репорт.** Но если одна причина проявляется на нескольких элементах, дефект
раскладывается построчно: общий `Bug ID` и `Title` в первой строке, дальше по строке на каждый
затронутый элемент со своим `Related Case ID` и своим шагом. Так разработчик видит полный охват, а
трассируемость к кейсам не теряется.

**Фактический результат описывает наблюдаемое, а не предполагаемую причину.** «Цвет, фон и рамка не
изменяются» — наблюдение. «Не подключён CSS для hover» — гипотеза, и она может быть неверной.

**Наблюдение описывается словами, замер остаётся в доказательствах.** «Внешний вид логотипа не
меняется: снимок до наведения и снимок под курсором ничем не отличаются» — годится.
«pixelDiff.changed = 0» и «`opacity: 0.8` → `1`» — нет, это язык инструмента. Ссылка на файл
замеров в `Attachments/Links` делает утверждение проверяемым, а текст оставляет читаемым.

**Доказательство обязательно для всего, что не следует из ТЗ буквально.** Ссылка на запись экрана
или скриншот. В формате отчёта доказательства идут ссылками в колонке `Attachments/Links`, а не
вложенными картинками.

**Окружение указывается всегда.** Дефект без среды не воспроизводится и возвращается со статусом
«не воспроизвелось».

**Тон нейтральный.** Отчёт читают несколько человек, включая автора кода.

## Частые ошибки

- Шаги «зайти на сайт и попробовать» — не воспроизводится.
- Ожидаемый результат без источника: спор превращается в вопрос авторитета.
- Скриншот всей страницы без указания, куда смотреть.
- Несколько независимых дефектов в одном репорте: часть починят, часть потеряют.
- Дефект без `Related Case ID` — выпадает из трассируемости, валидатор отчёта его не пропустит.

## Проверка

- Дефект воспроизведён по собственным шагам на чистой сессии.
- Указаны браузер, версия, ОС, разрешение.
- Приложено доказательство ссылкой.
- Каждый `Fail` в прогоне ссылается на существующий `Bug ID`, у каждого `Pass` поле пустое.
