# Матрица трассируемости

Связь «требование → кейс → результат прогона → дефект». Отвечает на два вопроса: всё ли покрыто и
что именно сломано относительно требований.

## Когда использовать

- Есть формальные требования или список критериев приёмки.
- Заказчик спрашивает про покрытие, а не про число найденных багов.
- Продукт сдаётся этапами и нужно показать, что закрыто.

## Когда не использовать

- Требований нет вообще. Тогда роль матрицы играет чек-лист: покрытие считается относительно его
  пунктов.
- Разовая проверка на несколько часов — накладные расходы не окупятся.

## Как это делается

В формате отчёта матрица не выделена отдельным листом: её роль выполняет сквозная связка колонок.

- `Test Cases.Case ID` → `Test Run.Case ID` — каждый кейс имеет результат;
- `Test Run.Bug ID` → `Bug Reports.Bug ID` — каждый провал имеет дефект;
- `Bug Reports.Related Case ID` — обратная ссылка от дефекта к кейсу.

Это даёт трассируемость внутри прогона. Связь с требованиями добавляется в `_qa-cases.md`: у каждого
кейса указывается покрываемое требование или пункт чек-листа.

Простая форма для заказа без формальных требований:

| Пункт чек-листа | Кейсы | Результат |
|---|---|---|
| Логотип ведёт на главную | TC-002 | Pass |
| Реакция элементов шапки на наведение | TC-001, TC-003, TC-005, TC-007 | Fail (BR-001) |
| Валидация пароля | TC-015 | Pass |
| Оплата картой | — | не покрыто: нет тестовой среды |

Строка «не покрыто» так же важна, как остальные: она превращает молчаливый пропуск в зафиксированное
решение.

## Практика

- Матрица строится до прогона, а не после: её задача — обнаружить пробел в покрытии, пока его ещё
  можно закрыть.
- После прогона матрица показывает, какие требования затронуты дефектами. Это основание для оценки
  готовности в отчёте.
- Автоматическая часть трассируемости проверяется валидатором отчёта: `Fail` без `Bug ID` и `Pass` с
  `Bug ID` файл не пройдёт.

## Частые ошибки

- Матрица, составленная после прогона: она документирует сделанное, а не управляет покрытием.
- Отсутствие строк «не покрыто» — пробелы становятся невидимыми.
- Один кейс на требование из пяти условий: покрытие формальное, фактически проверена одна ветка.
- Ручное сопоставление кейсов и дефектов в отчёте без проверки — источник битых ссылок.

## Проверка

```
python tools/verify-qa-report.py <отчёт>.xlsx
```

Валидатор ловит разрывы трассируемости механически. Дополнительно вручную:

- каждый пункт выбранных чек-листов присутствует в матрице;
- непокрытые пункты имеют причину;
- требование с несколькими условиями покрыто более чем одним кейсом.
