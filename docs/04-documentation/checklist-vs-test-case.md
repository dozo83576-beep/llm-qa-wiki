# Чек-лист против тест-кейса

Два формата фиксации проверок с разной ценой и разным назначением. Выбор между ними — решение об
экономике заказа, а не о качестве оформления.

## Когда использовать чек-лист

- Проверку выполняет тот, кто её придумал.
- Область знакомая, шаги очевидны: «логотип ведёт на главную».
- Времени мало, покрытие важнее детализации.
- Исследовательская сессия: чек-лист как карта, а не как сценарий.

## Когда использовать тест-кейс

- Проверку будет выполнять другой человек.
- Сценарий длинный, порядок шагов важен, есть предусловия.
- Результат идёт в отчёт заказчику со сквозной трассируемостью.
- Проверка войдёт в регрессионный набор и будет повторяться.
- Логика неочевидна: расчёт скидки, права доступа, переходы состояний.

## Различие

**Чек-лист** — список того, что нужно проверить. Пункт формулируется как проверяемое утверждение:
«поиск по пустому запросу показывает корректное сообщение». Ожидаемый результат подразумевается,
шагов нет.

**Тест-кейс** — воспроизводимый сценарий: предусловия, пронумерованные шаги, измеримый ожидаемый
результат, постусловия, приоритет. Формат — [тест-кейс](test-case.md).

Цена различается кратно: чек-лист на 30 пунктов пишется за час, 30 тест-кейсов — за день.

## Практика

Рабочая комбинация на веб-заказе:

1. Взять готовый чек-лист из `checklists/` под тип объекта.
2. Пройти его исследовательской сессией — так находится основная масса дефектов.
3. Превратить в тест-кейсы только то, что идёт в отчёт: критичные сценарии, найденные дефекты,
   области с высоким риском.

Так покрытие обеспечивается чек-листом, а трассируемость отчёта — кейсами. Писать кейсы на все
пункты чек-листа до прогона — типовой способ потратить бюджет до начала поиска дефектов.

## Частые ошибки

- Кейсы на всё подряд: бюджет уходит в оформление, дефекты искать некогда.
- Чек-лист там, где нужна воспроизводимость: другой исполнитель проверит иначе и получит другой
  результат.
- Пункт чек-листа без проверяемого утверждения: «проверить корзину» — непонятно, что считать успехом.
- Кейс без предусловий: сценарий не воспроизводится на чистом аккаунте.

## Проверка

- Каждый пункт чек-листа сформулирован как проверяемое утверждение.
- Кейсы написаны там, где нужна передача другому исполнителю или трассируемость в отчёте.
- Соотношение времени на оформление и на поиск дефектов не перевёрнуто.
