# Схема `_qa-report.json`

Вход генератора отчёта. Промежуточный формат между рабочими артефактами фаз и конечным XLSX: данные
один раз собираются в структуру, дальше сборка и проверка идут механически.

## Когда использовать

- Фаза `qa-report`: свести `_qa-cases.md`, `_qa-run.md` и `_qa-defects.md` в один файл.

## Когда не использовать

- Как рабочий формат в ходе прогона. Заполнять JSON по ходу неудобно; он собирается в конце.

## Структура

```json
{
  "project": "Example",
  "site": "https://example.test/",
  "environment": "Chrome 150, Windows 10",
  "tester": "Николай",
  "session": { "id": "TR-001", "name": "Проверка шапки", "date": "2026-07-30" },
  "cases": [ ... ],
  "run": [ ... ],
  "defects": [ ... ]
}
```

**Кейс:**

```json
{
  "id": "TC-001",
  "title": "Шапка: hover-эффект логотипа",
  "preconditions": "Открыта страница https://example.test/. Курсор вне шапки.",
  "steps": ["1. Навести курсор на логотип.", "2. Наблюдать состояние 0,3 секунды."],
  "expected": "Логотип визуально реагирует на наведение.",
  "postconditions": "Страница не изменена.",
  "priority": "Low"
}
```

`steps` принимает список строк или одну строку с переносами.

**Строка прогона:**

```json
{ "case": "TC-001", "result": "Fail", "comment": "Стили до и после совпали.", "bug": "BR-001" }
```

У `Pass` поле `bug` пустое. У `Fail` — обязательно заполнено.

**Дефект.** Массив `rows` — то, как дефект раскладывается построчно по затронутым элементам:

```json
{
  "id": "BR-001",
  "title": "Нет hover-эффекта у элементов шапки",
  "severity": "Minor",
  "priority": "Medium",
  "link": "evidence/TC-001.png, evidence/TC-002.png, evidence/run-journal.json",
  "reported": "2026-07-30",
  "rows": [
    {
      "case": "TC-001",
      "preconditions": "Открыта https://example.test/.",
      "step": "Навести курсор на логотип.",
      "expected": "Элемент получает визуальную реакцию.",
      "actual": "Цвет, фон и рамка не изменяются.",
      "link": "evidence/TC-001.png"
    }
  ]
}
```

Поле `environment` у дефекта необязательно: без него берётся значение из корня.

Поле `link` у строки необязательно. Без него генератор сам раскладывает список дефекта по строкам:
каждой достаются файлы, чьё имя начинается с её `case`, плюс файлы без Case ID в имени — журнал
прогона нужен всем строкам. Так строка про `TC-021` не ссылается на кадры соседних кейсов. Правило
именования — в [сборе доказательств](../09-automation/evidence-collection.md).

## Правила

Генератор отклоняет файл, нарушающий любое из условий, с русским сообщением:

- нумерация кейсов сплошная с `TC-001`;
- прогон покрывает все кейсы в том же порядке;
- `Fail` имеет существующий `bug`, `Pass` — пустой;
- `priority`, `severity`, `result` — только значения из справочников;
- у дефекта есть хотя бы одна строка в `rows`.

## Частые ошибки

- Ручная правка собранного XLSX вместо правки JSON: следующая пересборка затрёт изменения.
- Дефект без `rows`.
- Ссылка на кейс, которого нет в `cases`.
- Даты в произвольном формате: принимаются `YYYY-MM-DD` и `YYYY-MM-DD HH:MM`.

## Проверка

```
python tools/build-qa-report.py --input _qa-report.json --out outputs/QA_Проект_2026-07-30.xlsx
```

```
python tools/verify-qa-report.py outputs/QA_Проект_2026-07-30.xlsx
```

Источник правды — JSON. Правки вносятся в него, отчёт пересобирается.
