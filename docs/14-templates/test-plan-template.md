# Шаблон тест-плана

Заготовка для `_qa-plan.md`. Разделы, не относящиеся к заказу, удаляются; недостающие добавляются.

## Когда использовать

- Фаза `qa-plan` любого заказа длиннее одного дня.

## Когда не использовать

- Разовая проверка одной формы: достаточно чек-листа.

## Шаблон

```markdown
# Тест-план: <проект>

## Объект
- Что тестируется: <URL / сборка / версия>
- Дата и версия объекта: <...>

## Вне скоупа
- <область> — <причина: нет доступа / вне договора / отдельный этап>

## Окружение
- Стенд: <адрес>
- Браузеры и устройства: <перечислить поимённо>
- Разрешения: <360, 768, 1440 px, ...>
- Учётные записи: <роли>
- Доступы: <почта, платёжная песочница, логи>

## Виды тестирования
| Вид | Почему выбран | Объём |
|---|---|---|
| функциональное | есть формы и оформление заказа | полный |
| UI | есть макеты | сверка ключевых экранов |
| совместимость | публичный сайт | матрица выше |

## Риски и приоритеты
| Область | Вероятность | Ущерб | Риск | Объём проверок |
|---|---|---|---|---|
| <...> | 1-3 | 1-3 | <произведение> | <...> |

## Entry criteria
- Сборка развёрнута на стенде
- Доступы и тестовые данные получены
- Smoke проходит

## Exit criteria
- Все запланированные кейсы выполнены
- Нет открытых дефектов Critical и Major
- Дефекты Minor зафиксированы и приняты заказчиком
- Ключевые сценарии пройдены на всех средах из матрицы

## Тестовые данные
- <перечень требуемых записей и учётных записей>

## Оценка
| Область | Часы |
|---|---|

## Результат
- Формат: XLSX Test Management
- Доказательства: ссылками, хранилище <...>
- Дата готовности отчёта: <...>
```

## Частые ошибки

- Пустой раздел «Вне скоупа» — главный источник споров при сдаче.
- Exit criteria без чисел и проверяемых условий.
- Матрица сред словами «основные браузеры».
- План, не согласованный письменно до начала работ.

## Проверка

- Раздел «Вне скоупа» заполнен с причинами.
- Каждый вид тестирования обоснован свойством объекта.
- Exit criteria измеримы.
- План согласован до старта.
