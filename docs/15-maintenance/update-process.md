# Как обновлять вики

Правила внесения изменений. Цель — чтобы вики росла содержательно, а не дублировала саму себя.

## Когда использовать

- Фаза `qa-capture` после заказа.
- Найдено что-то, что пригодится в следующий раз.
- Обнаружено, что документ устарел или неверен.

## Когда не использовать

- Нет свидетельств: ни подтверждения от заказчика, ни замера, ни воспроизведённого случая. Тогда
  фиксировать нечего, так и записывается.

## Куда что пишется

| Что произошло | Куда |
|---|---|
| Повторяемый приём | `patterns/<область>/<имя>.md` |
| Успешный проект | `case-studies/successes/YYYY-MM-DD-<slug>.md` |
| Провал или инцидент | `case-studies/failures/YYYY-MM-DD-<slug>.md` |
| Короткий вывод | `lessons-learned/YYYY-MM-DD-<тема>.md` |
| Новый критерий проверки | `checklists/<имя>.md` |
| Типовой дефект | `bug-taxonomy/<имя>.md` |

## Правила

**Обновлять, а не дублировать.** Перед созданием нового файла — поиск существующего:

```
pwsh tools/ask-wiki.ps1 "<тема>"
```

**Кейс ссылается, а не хранит.** Разбор проекта не пересказывает найденные приёмы: он выносит их в
паттерны и уроки и ссылается на них. Так знание переиспользуется, а кейс остаётся коротким.

**Каждый урок заканчивается проверяемым правилом.** Секция «Как поймать» с конкретной проверкой:
регулярное выражение, команда, пункт чек-листа. Урок без неё — рассказ, а не знание.

**Обезличивание.** Названия и URL заказчиков, реальные данные и содержимое договоров в вики не
попадают. Кейс описывает тип объекта, а не клиента.

**Дата — реальная.** `updated` меняется при содержательной правке. Перечитал и не менял — ставится
`reviewed`, а не подкручивается `updated`.

**Неверное удаляется.** Документ, оказавшийся ошибочным, исправляется или помечается `archived`.
Оставлять неверное «на всякий случай» опаснее, чем не иметь ничего.

## Порядок правки

1. Найти существующий документ по теме.
2. Внести изменение, обновить `updated`.
3. Проверить, не появилось ли дублирование с соседними документами.
4. Прогнать гейт.

```
pwsh tools/ci-local.ps1
```

Менялись скиллы — раскатать канон в оба рантайма, иначе они останутся на старой версии:

```
pwsh agent-skills/sync-skills.ps1
```

## Частые ошибки

- Новый файл вместо правки существующего — вики распухает, поиск выдаёт противоречия.
- Урок без секции «Как поймать».
- Кейс, пересказывающий приёмы вместо ссылок на паттерны.
- Массовая простановка одинаковой даты `updated` — CI это замечает.
- Коммит без прогона гейта.

## Проверка

- Гейт проходит.
- Новый документ не дублирует существующий.
- Каждый урок содержит проверяемое правило.
- В записи нет данных заказчика.
- Скиллы раскатаны в оба рантайма, если менялись.
