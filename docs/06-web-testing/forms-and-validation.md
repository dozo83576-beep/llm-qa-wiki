# Формы и валидация

Формы дают больше дефектов, чем любая другая часть сайта. Причина в том, что валидация обычно
существует в двух местах — на клиенте и на сервере — и они расходятся.

## Когда использовать

- На сайте есть любая форма: обратная связь, регистрация, вход, заказ, подписка.

## Когда не использовать

- Статический сайт без единого поля ввода.

## Что проверять

**Обязательность.** Незаполненное обязательное поле блокирует отправку и подсвечивается. Обязательные
поля помечены визуально. Незаполненное необязательное не вызывает ошибку.

**Длина и содержимое.** По [эквивалентным классам](../03-test-design/equivalence-partitioning.md) и
[границам](../03-test-design/boundary-value-analysis.md): минимум, максимум, на единицу за пределом.
Спецсимволы. Пробелы в начале и конце — должны обрезаться. Строка только из пробелов не считается
заполненным полем.

**Числовые поля.** Буквы отклоняются с понятным сообщением. Дробные: проверить и `1.1`, и `1,1`.
Отрицательные там, где не имеют смысла. Ведущий ноль. Очень большое число.

**Специфические форматы.** Email без `@`, без домена, с пробелом, с кириллицей. Телефон с буквами и
спецсимволами. ФИО с цифрами. Дата в прошлом там, где ждут будущее.

**Двойная отправка.** Двойной клик по кнопке. Повторная отправка через Enter. Один из самых частых
источников дублей заявок.

**Сохранность введённого.** При ошибке валидации заполненные поля не очищаются. При случайной
перезагрузке длинного сообщения данные не теряются.

**Доставка.** Форма не считается работающей по надписи «Спасибо». Проверяется приход письма или
заявки в согласованный канал.

## Клиент против сервера

Клиентская валидация — удобство, серверная — защита. Проверять нужно обе:

- заполнить поле в обход `maxlength` через инструменты разработчика или прямой запрос;
- отправить форму с отключённым JavaScript;
- отправить запрос напрямую с невалидными данными.

Отсутствие серверной валидации — дефект, даже если через интерфейс он недостижим. Severity зависит
от того, что попадает в базу.

## Частые ошибки

- Проверка только happy path и одного невалидного значения.
- Доверие надписи об успехе без проверки доставки.
- Пропуск двойного клика.
- Проверка только клиентской валидации.
- Игнорирование текста сообщения об ошибке: «Ошибка» вместо указания поля и правила — это дефект
  уровня `Minor`, а не мелочь.

## Проверка

- Каждое поле покрыто кейсами на обязательность, длину и допустимые символы.
- Проверена двойная отправка.
- Подтверждена фактическая доставка в согласованный канал.
- Серверная валидация проверена в обход клиентской.
- Сообщения об ошибках называют поле и правило.
