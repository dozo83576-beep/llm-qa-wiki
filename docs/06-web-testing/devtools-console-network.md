# DevTools: консоль и сеть

Инструменты разработчика превращают наблюдение «вроде работает» в проверяемый факт. Открытая консоль
в течение всего прогона — самая дешёвая проверка с самой высокой отдачей.

## Когда использовать

- Постоянно, весь прогон.
- При оформлении любого дефекта: доказательство берётся отсюда.
- Когда поведение выглядит правильным, но результата нет.

## Когда не использовать

- Как замену пользовательской проверке. Чистая консоль не означает, что сценарий проходится.

## Консоль

Ошибки на ключевых страницах — дефект, даже если визуально всё в порядке: они означают, что часть
кода не отработала.

Различать:

- **Ошибки** — красное. Дефект почти всегда.
- **Предупреждения** — жёлтое. Оцениваются по содержанию: устаревшие API и нарушения политики
  безопасности значимы, шум сторонних виджетов обычно нет.
- **Ошибки загрузки ресурсов** — отсутствующие изображения, шрифты, скрипты. Видны как 404 в сети.

В баг-репорт текст ошибки копируется целиком, а не пересказывается.

## Панель сети

**Коды ответов.** 4xx и 5xx на штатном сценарии — дефект. Отдельно проверяется, что несуществующая
страница отдаёт именно 404, а не 200 с пустым телом.

**Отправка форм.** Основной способ отличить «форма работает» от «форма показывает „Спасибо“». Смотреть
надо на запрос: ушёл ли, с какими данными, что вернул сервер. Успешная надпись при ответе 500 —
частый дефект.

**Размеры и время.** Тяжёлые изображения, несжатые ресурсы, долгие запросы. Даёт основание для
замечаний по производительности с числами, а не на глаз.

**Передача данных.** Пароли и персональные данные не должны уходить в параметрах URL: они попадают в
логи и историю браузера.

**Повторные запросы.** Двойной клик по кнопке отправки виден как два одинаковых запроса — прямое
доказательство дефекта дублирования.

## Как это попадает в дефект

Доказательство из DevTools — самый сильный аргумент, потому что оно не зависит от интерпретации:

- код ответа и тело ответа сервера;
- текст ошибки консоли;
- вычисленные стили элемента до и после действия, см.
  [паттерн](../../patterns/ui/computed-style-hover-proof.md);
- запись экрана с открытой панелью — видно и действие, и запрос.

## Частые ошибки

- Прогон с закрытыми инструментами: ошибки консоли не попадают в отчёт вообще.
- Вывод об успехе формы по сообщению на странице без проверки ответа сервера.
- Пересказ ошибки своими словами вместо точного текста.
- Списание всех предупреждений на «шум» без разбора.

## Проверка

- Консоль была открыта в течение всего прогона.
- Для каждой формы зафиксирован код ответа сервера.
- Проверено, что 404 отдаёт корректный код.
- В каждом дефекте с участием сети приведены код и тело ответа.
- Проверено, что чувствительные данные не уходят в параметрах URL.
